Data contract

SOURCE OF TRUTH
<repo>/.codeview/daemon.json — { pid, port, repo, started_at, watch, max_commits, session }. A daemon counts as serving only if the pid answers os.kill(pid, 0) and its cmdline still looks like the codeview server, the same test bin/codeview status uses.
PLUMBING
fetch_sessions.py already joins every tmux session to its repo; it adds a per-session codeview: {present, running, port, indexAgeSeconds} block to cache/sessions.json — one stat of <repo>/.codeview/daemon.json, one /proc pid check, one small cache read per repo, on the existing 20 s fetch. No HTTP calls, no new loop, no fleet-wide scan.
MOTION
The moon's angle is os.time() / 420s × 360°, recomputed on every Cairo draw — nothing accumulates, so the drift survives restarts and pauses. Phase (index age) and the eclipse are computed states, not animations. The sessions window's update_interval goes 10 s → 1 s so the 420 s orbit steps ~0.86° (sub-pixel) per redraw — a crawl, never a jump; measured cost at that tick is ≤ 0.5 % CPU. Orbit direction flips per repo hash.
REPO TINT
The sessions bay hashes each repo name into a 10-color palette. The moon reuses that exact hash, so a repo's moon, its session diamonds, and its filaments all wear one color — e.g. conky-linear-HUP violet, clusterfork sky, k-suite-api lime.
DECIDED
Ship the moon on the session diamond. fetch_sessions.py already resolves each session's repo — it stats <repo>/.codeview/daemon.json, checks the pid, and reads the summary cache's scan time, writing a per-session codeview block into cache/sessions.json. The renderer draws the orbit and moon from os.time(), and the bay's window drops from a 10 s to a 1 s redraw tick so the 420 s orbit advances ~0.86° (about a quarter pixel) per frame — a continuous drift, never a jump. The fleet-panel readings (A, B, C, CTX) and the halo (D3) stay in this page as the runner-ups.
